# 四维推导轴（活动定位与查漏工具）

供 Step 2 行为改变、Step 5 创意机制前加载。用「七状态 × 两层对象 × 五形态 × 时空」辅助定位目标和活动形态；分类不能保证完备，还要用实际参与旅程、交接链和反例查漏。

> 先用需求信号查表，再核对真实目标、受众和限制；信号冲突时保留多种解释并验证，不为套表改写需求。不要求对外展示完整分析过程。

## 一、活动类型 = 四维的一个组合

```
活动类型 = 七状态目的 × 两层对象 × 五形态 × 时空
```

多数常见活动可用四维描述。无法定位时保留原需求并记录分类缺口，不因此否定活动，也不在运行中自行改动方法库。

## 二、七状态目的轴（查表定位）

| 需求信号（用户原话里的词） | 状态 | 典型活动 |
|---|---|---|
| 「要卖货 / 冲 GMV / 转化 / 促活」 | 行为 | 促销、招商、直播带货、体验店 |
| 「要让人知道 / 记住 / 造声量 / 占心智」 | 认知 | 发布会、媒体会、内容传播、快闪 |
| 「要让人喜欢 / 认同 / 归属 / 留人」 | 情感 | 答谢会、年会、粉丝见面、品牌演绎 |
| 「要拉近关系 / 结盟 / 答谢 / 留客」 | 关系 | 私享会、酒会、政企对接、答谢 |
| 「要钱 / 要渠道 / 要人 / 要数据」 | 资源 | 路演、招商、招聘、数据沉淀 |
| 「要剪彩 / 揭牌 / 签约 / 授牌 / 上市 / 奠基」 | 身份 | 开工仪式、揭牌、签约仪式、授牌 |
| 「要运动 / 提升体能 / 身体技能」 | 生理能力 | 健康跑、运动技能练习 |

> 七状态是启发式分类，可组合。培训须区分知识理解、技能练习与工作行为迁移：分别核对学习前基线、练习表现和应用结果；不能统一归为身体能力。体检通常提供健康信息或服务，不自动证明身体能力改善。仪式也不能替代真实资格或合同效力。

## 三、两层对象轴

| 层 | 含义 | 例子 |
|---|---|---|
| 参与者 | 谁来现场 | 消费者 / 员工 / 媒体 / 领导 / 公众 |
| 受益者 | 谁最终获益 | 多数活动两者重合；公益/环保/CSR 两者分离（受益者是环境/弱势群体） |

**硬规则**：两者分离的活动（公益、环保、CSR），必须分别写清「参与者是谁、受益者是谁」，别混成一谈。

## 四、五形态轴（参与者与活动的关系）

| 形态 | 参与者角色 | 例子 |
|---|---|---|
| 接受 | 被动看/听 | 发布会、演讲、展览 |
| 参与 | 主动做/玩 | 快闪、体验店、游戏化 |
| 仪式 | 完成象征动作 | 剪彩、颁奖、签约 |
| 连接 | 建立人际连接 | 酒会、私享会、答谢 |
| 共创 | 产出内容 | UGC、挑战赛、内容共创 |

## 五、时空轴

线下 / 线上 / 混合 × 单次 / 周期。

- 「线上型」活动（Webinar / 线上发布会 / AMA / 虚拟活动）是「形态+时空」的组合，不是独立目的——它落进「时空轴=线上」+ 对应目的。
- 「周期型」活动（会员日 / 月度社群活动）落进「时空轴=周期」。

## 六、推导路径记录（强制）

每个创意/方案，内部必须标注一条推导路径。默认写入决策依据文件或过程记录；阶段输出和正式方案正文不展示，除非它直接影响用户选择或用户要求展开。格式：

```
[七状态] → [参与者/受益者] → [形态] → [时空]
例：行为 → 消费者/消费者 → 参与 → 线下/单次
例：身份 → 领导+员工/组织 → 仪式 → 线下/单次（剪彩）
例：资源 → 公众/环境 → 共创 → 混合/周期（公益）
```

这条推导路径是**贯穿全流程的线索**：Step 2/Step 5 生成，Step 7 对抗时攻击，Step 8 成案时验证，活动后进入 `output/case-library/` 或用户指定复盘文档。它不是一次性的标签。

## 七、用法（查表 + 落地，两步）

1. **查表定位**：拿需求信号词，对「七状态」表定位目的，再补「对象 / 形态 / 时空」。
2. **查案例锚点**：定位完，去 `event-types.md` 查对应类型的「核心要素 / 候选指标 / 翻车点」落地；按项目目标选择判据。

**分工**：axes.md 辅助定位与查漏，event-types.md 提供常见形式和案例线索。两者都不证明覆盖全部需求；与原案、实际操作和 `full-scope-check.md` 交叉核对。
