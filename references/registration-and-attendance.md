# 报名、票务与到场系统

本文件用于有外部报名、票务、邀约、签到、候补、到场率要求的活动。

## 一、触发条件

- 发布会、峰会、论坛、展会、招商会、私享会、快闪、市集、直播、线上/混合活动。
- 用户关心报名、到场、售票、邀约、名单、签到、留资。

## 二、报名/到场漏斗

必须拆成：

```
目标人群 → 邀约池 → 点击/回复 → 报名 → 确认 → 到场 → 现场互动 → 会后跟进
```

| 阶段 | 指标 | 责任人 | 数据来源 | 失败动作 |
|---|---|---|---|---|
| 邀约池 | 名单数、匹配度 |  | CRM/私域/渠道 | 补名单/换渠道 |
| 报名 | 报名数、完成率 |  | 表单/小程序/票务平台 | 降低表单阻力 |
| 确认 | 确认率 |  | 短信/私信/电话 | 增加提醒 |
| 到场 | 到场率、no-show |  | 签到/扫码 | 候补/二次提醒 |
| 互动 | 互动率、留资 |  | 现场任务/问卷 | 优化动线 |

## 三、表单字段原则

报名表要少而准：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 姓名/称呼或报名ID | 按签到需要 | 可匿名参与时不强制实名 |
| 手机/微信/邮箱 | 按场景必填 | 只收必要联系方式 |
| 公司/职位 | To B按任务需要 | 不为纯旁听强制收销售字段 |
| 参与方式 | 混合活动必填 | 线下/线上 |
| 需求/兴趣 | To B/课程/招商建议 | 用于会后跟进 |
| 餐饮/无障碍需求 | 线下活动按需 | 不得过度收集敏感信息 |
| 营销/赞助数据选择 | 涉及相应用途时分别说明 | 不默认勾选，不把非必要营销同意设为正常报名条件；核处理依据 |

## 四、票务与权益

| 类型 | 适用 | 注意 |
|---|---|---|
| 免费报名 | 私域、品牌活动、社区活动 | no-show 风险高，要提醒和候补 |
| 付费票 | 峰会、课程、演出、展会 | 需退款、发票、票种规则 |
| 邀请制 | VIP、闭门会、政企、私享会 | 不做公开报名页，重视 1v1 邀约 |
| 早鸟/团购 | 峰会、展会、课程 | 明确截止时间和权益差异 |
| 赠票/媒体票 | 嘉宾、媒体、赞助商 | 单列配额，防止挤占核心人群 |

## 五、no-show 管理

免费活动必须设计 no-show 预案：

- T-7、T-3、T-1、当天早上提醒。
- 重要嘉宾或 To B 决策人用 1v1 确认，不只群发。
- 设置候补池，明确候补触发时间。
- 高价值小场可设置保证金、确认回执或专属座位。

## 六、签到与失败备份

| 项目 | 要求 |
|---|---|
| 签到方式 | 二维码、名单、胸卡、手环、人工确认按场景选择 |
| 峰值排队 | 预估高峰，设置快慢通道 |
| 身份识别 | To B 可用胸卡颜色/标签区分角色 |
| 系统失败 | 离线名单、手写胸卡、备用网络、纸质签到表 |
| 数据回收 | 签到数据当天导出，和报名表匹配 |

## 七、交付清单

有报名/票务活动必须准备以下交付表。Step 6 阶段聊天只给关键结论和最大卡点；完整表进入执行附件或决策依据文件。

| 表 | 内容 |
|---|---|
| 报名漏斗表 | 各阶段目标、负责人、数据源 |
| 表单字段表 | 字段、必填、用途、合规说明 |
| 提醒节奏表 | 时间、触达方式、话术方向 |
| 签到方案 | 入口、人员、设备、失败备份 |
| 到场降级方案 | 到场不足时如何补人、补内容、补传播 |

## 数字与队列
人数分别记录邀约、有效报名、确认、到场、现场临时登记、赠票、工作人员；不同队列不能直接当漏斗分母。场地核同时在场总人数与批准布局，工作人员/演员也占容量。签到按高峰到达、服务时长、工位、可用时间估算吞吐；理论上限不保证实际排队体验，须留缓冲并预演。提醒节奏按活动临近程度、用户许可和退订调整，不必机械发送四轮。

## 票券、服务容量与售后状态

付费、限量名额、跨店优惠或预约服务触发。按订单/权益ID记录商品或服务规格、渠道、适用日期/时段、价格与叠加规则、可售/预占/已付/已核销或履约/退款/释放状态、操作者和依据。票务方核支付与票状态，经营方核实际可服务量，客服用同版条款处理异常，财务核清算；计划字段不代表系统已实现。

跨渠道使用可靠共享库存或事前拆分额度；预占注明失效释放规则。支付回调、补单和人工兑换先查现状，同一订单/动作键不能重复发券、扣库或退款。系统故障采用可追溯的限额人工登记，恢复后对账；不能把离线多点各自售出的数量当同一可售库存。

门票不等于签售、课程、礼品等附加权益；分别核容量与缺席/超时补救。房晚、餐位、教师/班次、体验预约按日期时段核真实承接，不用总销量替代可约量。商品展示、房源或样板绑定编号、供应状态、价格有效期、展示与交付差异和核验方；未经确认的师资、同款或交付范围不作承诺。

跨商户满减记录订单明细、租户、补贴承担者、叠加条件及部分退货分摊；退款后核赠品、核销、库存和结算的处理，不默认所有权益都释放。经营方确认餐段、出餐能力、缺货替代与预约限制，购买前说明。取消、退票、改期、超售分别列触发、受理人、期限、接收凭证与异常升级；验收用重复通知、最后名额并发、部分退款和缺货案例，不只看售票页面是否存在。
