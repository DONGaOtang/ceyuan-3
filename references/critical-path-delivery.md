# 关键路径与交付系统

本文件用于 Step 6 交付系统设计、Step 8 全案执行版、Step 9 交付一致性终审。目标是把方案变成可排产、可验收、可压缩的项目系统。

## 一、触发条件

- L/XL 活动、正式提案、跨部门、跨供应商、多场地、多城市。
- 涉及搭建、AV、直播、嘉宾、媒体、政府审批、赞助商履约。
- 用户要求全案执行、落地排期、Run of Show、供应商协同。

不满足以上条件时，不要把方案写成制片手册。S/M 级创意方案只需要列关键执行假设、关键路径摘要和明显风险；完整 SOP、点位图、call sheet、物料进出场表属于执行交付附件，不是所有策划案的默认正文。

## 三、T-minus 倒排原则

按活动日倒推，不要只写自然日期。

| 阶段 | 重点 |
|---|---|
| T-60/T-45 | 目标、预算、场地、主叙事、核心供应商 |
| T-30 | 报名/邀约启动、主视觉、嘉宾、传播计划、审批材料 |
| T-14 | 物料下单、Run of Show、人员分工、媒体/嘉宾确认 |
| T-7 | 现场动线、签到名单、提醒、供应商会、应急预案 |
| T-3 | 全流程彩排、物料到位、数据表、话术和主持确认 |
| D-day | 现场执行、异常记录、素材采集、数据回收 |
| T+1/T+3/T+7 | 感谢、线索跟进、复盘数据、传播长尾、财务核对 |

## 五、当天 Run of Show

执行级线下/直播/混合方案应准备对应当天 Run of Show；早期提案仅需关键节奏。Step 6 阶段聊天只给关键路径摘要；完整表进入执行附件或决策依据文件。

| 时间 | 环节 | 地点 | 用户动作 | 工作人员动作 | AV/物料 | 负责人 | 备用方案 |
|---|---|---|---|---|---|---|---|

当天流程和倒排期不能混在一张表里。

## 六、设计制作交接边界

设计物料没有通用固定规格。尺寸、材质、出血、文件格式、安装方式、制作周期、版权授权、打样轮次，取决于场地、供应商、媒介和预算。

触发条件：

- 用户要求可执行全案、供应商 Brief、物料制作或现场搭建。
- 方案包含主视觉、舞台、导视、展陈、印刷、屏幕内容、快闪装置、礼品包装。
- 已知场地、点位、屏幕比例、印刷或制作供应商要求。

触发后必须补齐：

| 物料 | 使用位置 | 尺寸/比例 | 材质/媒介 | 数量 | 交付格式 | 依赖 | 截止时间 | 验收标准 |
|---|---|---|---|---|---|---|---|---|

无法确定规格时，标为“待场地/供应商确认”，不要编造一个看似专业但不可执行的尺寸。

## 七、现场制片 SOP 边界

SOP 的作用不是让方案显得更完整，而是减少现场失败：人找不到、物料没到、车进不了、供电不够、网络断、嘉宾迟到、天气变化、责任无人认领。

触发条件：

- L/XL 活动、多供应商、多点位、多城市、直播/舞台/搭建/嘉宾/政府接待。
- 用户明确要求落地执行、现场手册、项目排期或供应商协同。
- 现场失败会造成安全、舆情、客户关系或重大成本损失。

触发后进入执行附件，不抢占正式方案主线：

| 模块 | 必备内容 |
|---|---|
| 点位图 | 签到、舞台、互动、展陈、餐饮、仓储、医务、消防通道 |
| Call sheet | 到岗时间、岗位、电话、负责人、替补 |
| 物料进出场 | 物料名、数量、到场时间、负责人、存放点、撤场方式 |
| 供应商通讯录 | 公司、接口人、电话、职责、到撤场时间 |
| 证件车辆 | 人员证件、车证、进场路线、装卸区 |
| 电力网络 | 用电点位、功率、网络需求、备份方案 |
| 应急记录 | 问题、发生时间、处理人、处理方式、复盘归因 |

## 八、压缩时间线原则

时间不足时可以并行，但不能跳过：

- 合规/审批/消防/安全。
- 核心环节彩排。
- 报名和到场确认。
- 主持/嘉宾/销售话术对齐。
- 数据采集表和负责人确认。

可压缩项：

- 定制物料。
- 大规模搭建。
- 非核心传播物料。
- 低价值礼品。
- 复杂互动支线。

## 九、交付一致性检查

Step 9 必须检查：

| 检查项 | 规则 |
|---|---|
| 人数 | 核同队列漏斗、同时人数和容量、服务库存；不同阶段人数不要求数值相等 |
| 时间 | 审批、设计、制作、搭建、彩排能按依赖完成 |
| 预算 | 分项、总额、应急金、不可砍项一致 |
| 权益 | 赞助承诺有现场资源和传播资源支撑 |
| 数据 | KPI 有采集点、负责人和工具 |
| 销售 | To B 活动有识别、评级、跟进、CRM 回填 |

亲子/未成年人或线上线下混合活动，按scenario-operation-cards.md选择对应操作卡；非命中场景不加载。

## 十、分区分时、人员与技术交接

执行级有多个点位/批次时，记录每区每时段预计进入/离开、同时人数、场地方确认容量、服务周期（含准备、登录、消毒、复位）、可用工位与队列溢出措施。总体人数合格不覆盖热门区聚集；用实测周期校正理论吞吐。装卸、摆渡、停车、转场及离场回程各核时间窗、载客/装卸能力和故障替代。

人员记录岗位资质/培训、班次、休息、替岗和跨区路程；一组可共享人员按同一时段总需求核容量，不能把每岗位都当独立满配。check_plan.py只核声明的独占资源，共享池与休息安排另留人工核验。关键岗位缺席时由已培训替补接手，否则降级/暂停。

效果图不等于工程设计。涉及搭建、电力、吊挂等时，由相应专业供应商/场地方确认图纸版本、负载与安装条件、验收及变更；更换设备/结构须重新交接。技术备份核共同故障：同一供电、网络、账号或单一操作员失效时不能称独立冗余。混合互动使用既有操作卡，并在Run of Show写发令方、现场/远端接令确认、超时和回退点。

## 十一、停止、升级与恢复

按真实故障风险列最小指挥记录：异常及触发依据、发现岗位、立即停止的动作、负责人及替补、接手专业方、通知对象/渠道、替代措施、恢复条件、确认人、时间与回执。范围只停受影响动作；现场危险由现场专业人员判断，模型不生成未经核实的医学处置或工程阈值。

开场/放行前由实际责任方核场地、资源、岗位、专业条件及未关闭阻断；缺证据可交条件式方案但不能假称已放行。医疗支持按风险核现场联络、急救资源、救援进入路线、转运交接及隐私记录；不得把“拨打急救电话”当全部安排。停止后先由专业方确认条件恢复，再由现场总控通知相关岗位重启；记录谁收到通知，不能因观众催促自动恢复。

演练选择最可能且影响大的故障，并测试替补人及共用资源失效；结果区分桌面预演、现场实测和未验证。车辆、生产参访、成人户外等使用professional-operation-cards.md，照护和产品接触使用service-fulfillment-cards.md，不限于亲子卡触发。
