# 实验验证层 · AB 测试 + 最小预检

先按 `ab-test-routing.md` 选择验证层级，再使用本文的实验记录。

供 Step 5 创意机制、Step 7 对抗、Step 8 成案、活动后复盘使用。核心一句话：**审查发现潜在失败条件，实验提供限定条件下的真实反应；两者都不保证成功。**

活动行业不总是适合严格 50/50 AB 测试；预算、样本、周期、渠道都可能受限。所以这里统一叫「实验验证层」，AB 测试只是其中一种。原则是：凡是方案依赖关键假设，就先用最小成本验证，不要把会议室判断当市场反馈。

## 一、触发条件

优先为高影响且未被可靠证据支持的假设设计验证；以下为需要考虑的信号，不自动要求公开AB：

- 创意依赖「用户愿意来 / 愿意发 / 愿意买 / 愿意信 / 愿意记住」。
- Step 7 对抗审查里出现高严重度不确定性。
- 方案进入 B/C/D 档，或活动体量进入 M/L/XL，或者活动面向外部受众。
- 活动结果要向老板、客户、赞助商、投资人证明。

不触发时也可以做轻量预检，但不要为了显得专业强行设计复杂实验。

## 二、实验对象

优先测试关键假设，不测试整套大方案。整套方案可比较总体结果，但难以归因到单个元素，须说明设计限制。

| 假设类型 | 要验证的问题 | 可测试对象 |
|---|---|---|
| 来不来 | 受众有没有非来不可的理由 | 邀约标题、嘉宾阵容、福利、稀缺名额 |
| 发不发 | 传播钩子是不是自嗨 | 海报标题、打卡点、话题名、短视频脚本 |
| 买不买 | 转化机制是否有效 | 权益包、优惠机制、成交话术、CTA |
| 信不信 | 背书是否足够 | 客户证言、案例、数据、嘉宾身份、媒体背书 |
| 记不记 | Big Idea 是否能被复述 | 活动名、主视觉、峰值仪式、结束动作 |
| 跑不跑得通 | 执行链路会不会崩 | 签到动线、互动机制、直播链路、彩排流程 |

## 三、实验设计格式

先记录共同字段：待验证假设、适用人群/场景、方法及选择理由、资料或样本来源、事先判据、观察结果与限制、失败后的调整。按方法补必要字段，不强迫每次都有A/B版本：

| 方法 | 补充字段 | 能得出的结论 |
|---|---|---|
| 访谈/观察 | 招募条件、拒访与未覆盖人群、问题提纲、支持与反例、记录位置 | 发现动机和问题线索；不能由少数受访者推断整体转化率 |
| 可用性检查 | 任务、完成条件、卡点、协助次数、退出原因 | 指定参与者在指定流程的可用性问题 |
| 彩排/故障演练 | 场景、注入异常、岗位、停止/恢复判据、实际回执 | 该情境下交接能否跑通；不需要制造A/B版本 |
| 方向性比较 | 比较方案、样本招募、暴露顺序、渠道差异 | 有限制的选择信号；非随机比较不能写成因果提升 |
| 随机对照试验 | A/B内容、分配单位、随机方式、样本量依据、周期、主指标、护栏、停止规则 | 满足设计和测量前提时估计限定范围的差异 |

**共同规则**：

1. 判据和决策动作提前写；事后改口径须留版本，不冒充预设。
2. 为解释单一因素而比较时，控制其他差异；比较整套方案或采用适当的多因素设计时可有多个变量，但不得把总体结果归给其中一个元素。
3. 小样本、便利招募、重复参会或数据缺失须报告限制；证据不足标未知。没有显著差异不等于两者等效。
4. 严格A/B需预设样本、周期、分配和停止规则，不依据中途波动随意宣布胜利。普通访谈和演练不套统计显著性要求。
5. 每种验证都写失败后的调整、复测或保守降级；专业风险演练由相应负责人确定安全边界，不实际制造危险。

## 四、复杂度分级

| 级别 | 实验要求 |
|---|---|
| S 轻量 | 有关键未知时选择1个快速预检：邀约话术 / 海报标题 / 私域投票 / 小范围访谈 |
| M 标准 | 按关键假设安排测试；无传播目标不测传播钩子 |
| L/XL 大型或战役级 | 内部形成完整实验计划：样本、渠道、周期、指标、护栏、决策阈值、降级路线；用户阶段输出只给关键验证动作和决策点 |

## 五、常见实验形式

- 邀约话术 AB：A 强调身份/稀缺，B 强调收益/福利，看点击、回复、报名。
- 海报标题 AB：A 情绪钩子，B 功能钩子，看点击率、收藏率、咨询率。
- 报名页 AB：A 短页直接报名，B 长页加强背书，看报名完成率和线索质量。
- 私域小样本预检：按决策需要招募可说明来源的目标用户看两个方向；人数是设计选择，不是统一合格线；，收集愿来理由和反感点。
- 销售/渠道预演：让一线人员用两套话术约客户，看实际反馈。
- 现场彩排验证：小规模跑签到、动线、互动、直播链路，记录卡点。

## 六、回填规则

活动后复盘不只回填「目标 vs 实际」，还要回填「实验结论」：

```
原假设 → 方法/方案版本 → 验证结果 → 实际活动表现 → 结论 → 下次复用/禁用
```

写回 `output/case-library/` 或用户指定复盘文档时至少记录，不得直接写回 `references/` 方法文件。跑测偏差写入 `output/run-reviews/`，方法论改进建议写入 `output/improvement-log/`：

- 哪个假设被验证 / 被推翻。
- 比较研究记录差异及可能解释；访谈记录支持与反例，演练记录通过点、故障和复测结果。
- 实验结果和最终活动结果是否一致。
- 如果不一致，是样本错、渠道错、执行错，还是现场变量改变。

**不回填实验结论，就无法证明人机协作在变强，只是在反复产出。**
