# To B 销售协同链

To B 活动不是活动当天结束，而是销售推进系统的一段。没有销售协同链的 To B 方案不完整。

## 一、完整链路

```
目标账户 → 邀约名单 → 销售话术 → 报名筛选 → 到场识别 → 现场互动 → 线索评级 → 24/48/72 小时跟进 → CRM 回填 → 二次会议 → 商机推进
```

## 二、必填字段

| 字段 | 写法 |
|---|---|
| 目标账户类型 | 行业、规模、区域、采购阶段、存量/新客 |
| 人群角色 | 决策人 / 影响者 / 使用者 / 采购 / 技术评估人 |
| 邀约名单来源 | 销售名单、CRM、渠道、协会、老客户转介绍、广告线索 |
| 销售邀约脚本 | 不能只发海报，要有角色化利益点 |
| 报名筛选 | 公司、职位、需求、预算、项目阶段、跟进销售 |
| 到场识别 | 签到标签、胸卡颜色、座位区、销售认领 |
| 现场互动 | 提问、圆桌、私聊、体验、需求卡、意向表 |
| 线索评级 | A/B/C 或 MQL/SQL，写清判定标准 |
| 会后跟进 | 24/48/72 小时动作 |
| CRM 回填 | 字段、负责人、截止时间 |
| 二次会议 CTA | 预约诊断、方案演示、报价会、POC、拜访 |

## 三、销售邀约脚本

按角色写，不要一套话术打所有人。

| 角色 | 邀约利益点 |
|---|---|
| 决策人 | 行业趋势、预算效率、风险、同行案例、战略判断 |
| 影响者 | 方案可行性、内部推动材料、成功案例 |
| 使用者 | 具体痛点、效率提升、体验、培训 |
| 采购 | 成本、服务边界、供应商稳定性、验收 |
| 技术评估人 | 架构、兼容性、安全、实施路径 |

## 四、线索评级

示例：

| 等级 | 标准 | 会后动作 |
|---|---|---|
| A / SQL | 有明确项目、预算、决策链、3 个月内推进 | 24 小时内销售跟进并约二次会议 |
| B / MQL | 有需求但预算/时间/决策链不完整 | 48 小时内发送资料包并做需求确认 |
| C / Nurture | 兴趣弱或周期长 | 72 小时内进入内容培育和私域标签 |

## 五、24/48/72 小时跟进

| 时间 | 动作 |
|---|---|
| 24 小时 | 感谢到场、发送核心资料、销售一对一触达 A 级线索 |
| 48 小时 | 推送案例/白皮书/回放，确认需求和采购阶段 |
| 72 小时 | 预约二次会议，CRM 回填，进入培育池 |

## 六、CRM 回填字段

至少包含：
- 账户名称。
- 联系人姓名与角色。
- 行业/区域/规模。
- 需求关键词。
- 预算或采购阶段。
- 活动互动记录。
- 线索评级。
- 归属销售。
- 下一步动作。
- 截止时间。

## 七、验收标准

To B 方案必须能回答：
- 谁邀约。
- 邀约谁。
- 用什么话术。
- 到场后怎么识别。
- 会后谁跟进。
- CRM 填什么。
- 如何推进到二次会议或商机。

只有活动当天流程，没有以上链路，判为不完整。

## 接手与业务状态

上述评级和24/48/72小时仅为候选节奏，按项目销售周期、接收容量与用户许可确认，不将所有弱意向自动加私域。线索ID对应接手人、接收/拒收时间、拒收原因、重派责任人和下一截止；“已分配”不等于“已接手”。实际写CRM或触达仍需授权及回执。

预约、已接手、已开始、已完成验证、签意向、签合同、落地、到账、交付分别按证据统计。SaaS POC交接需范围、客户技术前提、数据环境、双方资源、成功标准及接收确认；没人接手或条件未核只算预约。家装量房需区域、上门时段、设计师容量、接单回执及后续方案期限。招商签约只能报告文件证明的阶段，不能折算成实际投资或收入。

纯科普/关系活动无销售目标时不强加载销售链；招聘及危机承诺的会后关闭读data-capture-and-review.md对应分支。
