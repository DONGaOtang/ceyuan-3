# 行业要点（示例快速通道，非穷举）

本表是「常见行业示例 + 快速通道」，**不是穷举清单**——行业是无限、长尾、会过时的（宠物、电竞、婚庆、殡葬、滑雪……）。表里有的直接查（快），表里没有的走下方「行业判断 + 动态搜索」方法补充判断。

供 Step 2 行为改变、Step 5 创意机制、Step 6 交付系统按行业校准方案。五件套：**调性**（待验证的受众与品牌假设）、**风险提示**（需判断适用性）、**预算结构**（分配假设）、**合规核验项**（按行为、主体、地区和时间查证）、**候选模块**（按目标和实际操作选用）。按需取用，不全背。

## 行业判断 + 动态搜索（表里没有的行业走这里）

行业是无限、长尾、会过时的，硬编码清单补不完。表里没有的行业，按这套**动态判断 + 搜索**，现场生成五件套：

1. **提取行业信号**：从用户输入里抓「行业/领域」词（宠物、电竞、婚庆、殡葬、滑雪……）。
2. **归类到大类**：判断它属于消费 / 工业 / 文化 / 健康 / 专业服务……大类只提供候选方向，不决定调性；用品牌定位、目标受众、项目目标和反馈检验。
3. **动态生成搜索提示词**：`[行业词] + 活动策划 + 受众与品牌定位 / 风险 / 预算结构 / 适用要求 / 候选模块`，逐项去搜（检索路径见 `search-paths.md`，访问、登录、权限和降级见 `source-access-and-login-workflow.md`）。
4. **用横纵分析落地**：搜到的信息，走「拆解 + 对标」（`creative-inputs.md` 三）落成五件套，写入项目记录或 `output/improvement-log/`，不直接改本表。

> 关键：行业是「动态判断 + 搜索」出来的，不是「硬编码」出来的。硬编码的行业只是「常见示例」，是快速通道，不是兜底。别因为表里没有就卡住，也别为了「补全」而无限往表里加行业。

## 使用规则

1. **先对行业，再对活动类型**。同一场「发布会」，汽车和美妆的调性、预算、合规完全不同。表里查不到这个行业 → 走上方「行业判断 + 动态搜索」，别硬套最相近的行业。
2. **区分硬限制与风格假设**。法律、合同和品牌明确限制须有依据与适用范围；“贵气、亲民、热闹”等偏好不能直接否决方案。地产投诉属于服务问题，应建立接收与解决接口。
3. **合规核验项在 Step 6 交付系统和 Step 7 对抗审查按实际行为核适用性**。表中法规领域或许可名称不表示所有同业活动均适用。不熟悉的行业，联网核实最新法规；查不到、需登录、需权限或地区规则不明时，标“待验证/需当地核实”，别凭印象写。
4. **候选模块 = 具体清单层的选择提示**。进入环节设计时（Step 6），查本表「候选模块」列，作为「这个行业要列哪些清单」的骨架，再配合横纵分析的「细化」动作（`creative-inputs.md` 三）落到「需要哪些内容、细到什么程度」。这是查表取用，不是强制枚举——按已知需求自主选用，并说明关键取舍；信息不足只追问影响决策的内容。
5. **新增行业样本先沉淀，不直接改表**。动态搜索得到的长尾行业经验，先写入 `output/case-library/` 或 `output/improvement-log/`；经人工审核后再升级为本文件方法论。

## 专业操作按行为触发

行业名只提供索引，不等于所有候选模块都要做。实际命中后按需读取：

- 科技、3C、游戏、SaaS的联网演示/账户体验/设备复位，汽车和新能源的试乘试驾，医疗/医美的专业服务，金融产品服务，制造业生产参访、户外路线：`professional-operation-cards.md`。
- 食品/试用品接触、宠物照护、无障碍服务、票券与跨商户履约、房晚/预约、婚恋联系交换与婚庆供应交接：`service-fulfillment-cards.md`。
- 未成年人陪同/托管和混合直播另结合 `scenario-operation-cards.md`；新卡不替代已有接领、走失与直播细则。

记录触发行为、依据、专业负责人和核验状态；卡中条件未知时保留待核，不允许模型自行批准。业务场景最多三个的选择规则不限制这些适用检查。
