# 数据采集与复盘

本文件用于 Step 3 经营模型、Step 6 交付系统、Step 8 效果评估、Step 9 交付一致性审查。目标是活动前就设计好怎么证明，而不是活动后凭感觉复盘。

## 一、数据采集计划

每个 KPI 必须对应采集点：

| 指标 | 采集点 | 工具/系统 | 负责人 | 采集时间 | 数据口径 | 失败备份 |
|---|---|---|---|---|---|---|
| 报名数 | 报名表后台 | 小程序/表单/票务平台 |  | 每日 | 去重后报名人数 | 手工导出 |
| 到场率 | 签到 | 签到系统/纸质表 |  | D-day | 到场/报名 | 离线名单 |
| 互动率 | 现场任务 | 二维码/互动卡 |  | D-day | 完成互动人数/到场 | 人工计数 |
| 线索质量 | 销售跟进 | CRM |  | T+1/T+3 | A/B/C 或 MQL/SQL | 销售表格 |
| 内容资产 | 素材库 | 网盘/相册/剪辑表 |  | D-day/T+1 | 可用素材数 | 摄影清单 |
| 满意度 | 问卷/访谈 | 问卷星/飞书/电话 |  | T+1/T+3 | 有效样本数 | 1v1 访谈 |

## 二、口径规则

- 报名数要去重。
- 到场率 = 实际到场 / 有效报名。
- 线索要区分 MQL、SQL、Nurture。
- 曝光量要区分自然、投放、媒体、达人，不混算。
- UGC 要区分发布数、有效内容数、可复用授权数。
- 赞助数据要区分全场数据和单赞助商权益数据。

## 三、采集失败备份

每个关键数据都要有 B 方案：

| 失败 | 备份 |
|---|---|
| 签到系统崩 | 纸质名单 + 手工录入 |
| 问卷回收少 | 重点用户 1v1 访谈 |
| CRM 不配合 | 临时线索表 + 销售负责人签字 |
| 社媒数据拿不到 | 截图留证 + 链接归档 |
| 现场互动漏统计 | 抽样计数 + 摄影记录 |

## 四、复盘结构

活动后按目标回填适用项；无传播/叙事目标时省略叙事表现，不补造主场面：

| 模块 | 问题 |
|---|---|
| 目标 vs 实际 | 主判据赢了吗 |
| 四层链断点 | 投入、中间、结果、资产断在哪 |
| 实验结论 | 哪个假设被验证/推翻 |
| 叙事表现 | 主叙事是否被复述，主场面是否传播 |
| 执行表现 | 关键路径哪里延误，供应商哪里失控 |
| 数据质量 | 哪些数据没采到，为什么 |
| 下次动作 | 复用、禁用、重测、改目标、改机制 |

## 五、复盘会议

建议 T+7 内完成复盘会：

1. 先看主判据，不先讲感受。
2. 再看行为改变是否发生。
3. 有传播或叙事目标时，再看对应效果；无此目标省略。
4. 再看执行和预算偏差。
5. 最后决定下次复用/禁用/重测。

## 六、长闭环写回

活动结束后，把以下字段写回 `output/` 下的独立沉淀目录或用户指定复盘文档，不得直接写回 `references/` 方法文件：

- 活动类型和推导路径。
- 主叙事和创意机制。
- 目标 vs 实际。
- 断点层。
- 翻车点。
- 实验结论。
- 可复用动作。
- 禁用动作。

默认写入位置：

| 目录 | 内容 |
|---|---|
| `output/case-library/` | 成功/失败案例、创意机制、可复用动作、禁用动作 |
| `output/run-reviews/` | 跑测记录、验证偏差、调用失败、流程断点 |
| `output/user-projects/` | 用户项目阶段稿、过程输出、最终交付源稿 |
| `output/improvement-log/` | 需要人工审核后才可能升级为方法论的改进建议 |

只有经过人工审核的稳定规律，才允许从 `output/` 升级进 `references/`。

## 策元3数据质量核验
核数据来源/导出时间/观察窗口/时区、单位、去重键、缺失/异常、样本覆盖、报名队列、退款/取消、自然与付费、跨渠道重叠。原表只读保留，清洗另存并记录规则。百分比核分母；问卷记录回收率、有效样本与非响应偏差；访谈是质性补充，不替代总体定量结果。
每个结论带数据口径和限制。前后变化不等于因果；同比、同城对照也须说明混杂因素。不能把第三方估计当平台后台数据。使用授权、共享对象、最小字段、保留期限和删除责任按项目约定记录，未获授权不实际导出或共享个人数据。

涉及多家报价比较、预算削减或平台导出与报名/到场数据诊断时，按commercial-data-review.md执行对应分支，保留来源与口径。

## 数据流与关闭证据

涉及个人信息时记录采集目的与处理依据、必要字段、采集方、实际处理/受托/接收角色、访问权限、共享方式、保存与删除责任、请求联系人；根据实际关系核义务，不能用“已授权”替代全部判断。报名、营销、招聘、诊疗用途分开；健康结果仅交已核专业服务链，不自动进入销售线索。事件或更正/删除请求记录受理、保护措施、专业升级、通知要求适用核验及完成证据；没有真实执行不写已删数据。

复盘先核未关闭承诺：退款、赞助缺项、采购结算、资料交付、线索接收、数据处置；每项列接收人、截止、当前状态及证据，长期跟踪明确转交谁。活动结束或舆情降温不能代替兑现。危机沟通使用统一事实版本，客服、媒体和用户通知同步；承诺更改留通知与接收记录。

招聘活动将申请提交、岗位接收、评估、反馈和岗位关闭分别记录；岗位取消由招聘负责人接手通知，不默许简历转营销。培训目标与长期应用按metrics-flow.md；公益受益与物资去向按professional-operation-cards.md。沉淀案例注明项目条件、证据日期、适用范围及失败反例，不因一次成功升格成通用规律。
