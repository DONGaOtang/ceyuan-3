# 判局与任务范围

先区分plan/quick/review/module/retro；已有方案直接走plan-review.md。按目标、受众、委托关系、场域、时间地点、预算资源、读者、禁区确定临时路线。信息不足不按缺项数量卡住。

| 缺口 | 处理 |
|---|---|
| 不影响当前判断或可保留多种选择 | 明示假设继续 |
| 会改变主要目标、关键资源或形式 | 问最少的决定性问题，其余独立部分继续 |
| 涉及外部发布/投放/采购等新行动 | 在实际动作前取得对应授权 |

路径深度由任务决定，不只看预算：S最小方案；M常规项目；L/XL高依赖交付。风险、供应商和资源复杂度高时增强执行检查，小预算也可能有高风险。
主路由用一句话说明；仅对容易混淆的场景解释为什么不选另一条，不必逐项列排除路线。技术路由无需单独审批，但活动是否做、目标/受众/范围及关键约束进入Step 0决策卡，由用户确认；已有明确决定沿用，不为路由名重复问。
先判断活动是否适合目标；不适合则给更合适替代动作，不强行生成完整活动。
叙事按需求选择：价值说明/标准主线/强叙事；高预算和老板阅读不自动等于文旅或年度叙事。
已有完整资料先提取，不重复追问；关键矛盾并列记录。输出本次任务、已锁定内容、当前选项与影响、待用户决定项及可独立继续的工作。按user-decision-gates.md识别五入口的确认边界，信息齐全不意味着用户已选定所有方案。

## 业务路线与操作触发分别判断

业务路线决定目标和读者；风险与服务模块由实际动作决定，不受主辅场景数量限制。按full-scope-check.md记录命中/不适用/待核及依据，不能把未知当不适用。先从原需求识别收费退款、食物/产品接触、车辆、专业金融/医疗服务、托管、生产区域、户外、演出、赛事、募捐、个人数据等实际行为，再只读相关卡：

- 专业演示、车辆、金融/医疗、生产/户外、展会演出赛事公益：professional-operation-cards.md。
- 用户旅程、无障碍、食品试用、宠物、亲子私密、婚恋、社区、可持续：service-fulfillment-cards.md。
- 亲子照护与混合互动：scenario-operation-cards.md原有卡优先复用。

行业名只帮助发现触发，不构成专业服务资格或许可。提案级写可行性与待核，执行级才补岗位/凭证/停止恢复。单项任务只核关联触发；普通内部线上讨论不默认加载食品、票务、现场搭建等模块。
